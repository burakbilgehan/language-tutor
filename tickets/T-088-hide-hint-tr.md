## Problem

`chars[].hint_tr` (the small gray radical/component hint line under each
character card on the `/vocab` detail view, `VocabEntryView.tsx`) is
systematically hallucinated content, per the T-023 audit report (systemic
pattern 1, referenced but not independently re-read while implementing this
ticket). The field is generated by the vocab LLM prompt with no static
reference to ground it, so the "radical / phonetic component" hints are
frequently made up.

## Fix

1. Stopped rendering `hint_tr` in `VocabEntryView.tsx`; character cards keep
   char, reading, and meaning_tr.
2. Dropped the `hint_tr` request from the vocab generation prompt
   (`src/lib/llm/prompts/vocab.ts`) so future generations do not produce it.
3. Left the DB column and the `hint_tr: z.string().nullish()` schema field in
   `src/lib/llm/schemas.ts` untouched; historical rows keep the value, it is
   just no longer displayed or requested. No save-format or schema change.

## Result

- `VocabEntryView.tsx`: removed the `hint_tr` conditional paragraph under the
  character card (was lines ~239-241).
- `src/lib/llm/prompts/vocab.ts`: the `chars` bullet in the prompt now asks
  only for `{ "char", "reading", "meaning_tr" }`; the `hint_tr` clause is
  gone.
- `src/lib/llm/schemas.ts`: untouched, as scoped (`hint_tr` stays
  `nullish()`, existing DB rows keep their stored value, they are simply not
  read by the UI anymore).
- No test referenced `hint_tr` rendering directly, so no test changes were
  needed. `npm test` (246 tests) and `tsc --noEmit` both pass after the
  change.
- Packaged seed files (`public/vocab-seed/*.json`) and the LLM fixture
  bundle still carry `hint_tr` values from before this change; left alone
  per scope, they are inert now that nothing reads the field.
